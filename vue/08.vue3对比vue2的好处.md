## Vue3 对比 Vue2 的好处

### 性能更好

优化点                Vue2                                   Vue3

虚拟DOM               基于对象 diff，性能一般                    基于 Proxy + 静态标记（静态提升、Block Tree）更快

响应式系统             Object.defineProperty（只能监听已有属性）  Proxy（可监听对象新增、删除、数组下标等）

打包体积               Vue core ≈ 20KB+                        Vue core < 10KB（tree-shaking 更好）

组件初始化             每次全量更新                               编译时标记静态节点，只更新变化的部分


### composition Api

Vue 2 用的是 Options API（data、methods、computed、watch...），而 Vue 3 新增了 Composition API（setup、ref、reactive、watchEffect...）

1.逻辑更清晰：把相同功能的逻辑放在一起，而不是分散在不同选项里。


2.更易复用：通过封装自定义 hook（例如 useUser(), useFetch()）实现逻辑复用。

3.更好地支持 TypeScript：Composition API 原生支持类型推导

### 更灵活的组件系统

1.新增 Teleport

2. 新增 Suspense

3. 新增 Fragment

### Teleport 对比示例：有 / 无 Teleport 的差异

场景：父容器有 `overflow: hidden`，普通方式渲染的弹窗会被裁剪；使用 Teleport 后弹窗脱离该容器限制。

不使用 Teleport（弹窗被裁剪）：

```html
<template>
	<div class="card-wrapper">
		<button @click="show = true">打开弹窗(无 Teleport)</button>
		<div v-if="show" class="modal no-teleport">
			<div class="inner">被裁剪的弹窗 <button @click="show = false">关闭</button></div>
		</div>
	</div>
	<!-- 下面是其它内容 -->
</template>

<script setup>
import { ref } from 'vue';
const show = ref(false);
</script>

<style scoped>
.card-wrapper {
	width: 300px;
	height: 150px;
	overflow: hidden; /* 导致内部绝对定位元素超出部分不可见 */
	position: relative;
	border: 1px solid #ccc;
	padding: 16px;
}
.modal.no-teleport {
	position: absolute;
	top: 120px; /* 超出父容器高度 */
	left: 0;
	width: 280px;
	background: rgba(0,0,0,.6);
	color: #fff;
	padding: 12px;
	border-radius: 4px;
}
.inner { font-size: 14px; }
</style>
```

使用 Teleport（不被裁剪）：

```html
<template>
	<div class="card-wrapper">
		<button @click="open = true">打开弹窗(有 Teleport)</button>
	</div>
	<teleport to="body">
		<div v-if="open" class="modal teleport">
			<div class="inner">正常显示的弹窗 <button @click="open = false">关闭</button></div>
		</div>
	</teleport>
</template>

<script setup>
import { ref } from 'vue';
const open = ref(false);
</script>

<style scoped>
.card-wrapper {
	width: 300px;
	height: 150px;
	overflow: hidden; /* 仍然裁剪自身内容，不影响 Teleport */
	position: relative;
	border: 1px solid #ccc;
	padding: 16px;
}
.modal.teleport {
	position: fixed; /* 可以覆盖全局 */
	inset: 0;
	display: flex;
	justify-content: center;
	align-items: center;
	background: rgba(0,0,0,.45);
	z-index: 999;
}
.inner {
	background: #fff;
	color: #333;
	padding: 20px;
	border-radius: 6px;
	box-shadow: 0 4px 12px rgba(0,0,0,.15);
	font-size: 14px;
}
</style>
```

差异总结：
- 无 Teleport：弹窗 DOM 仍在受 `overflow:hidden` 影响的父容器内部，视觉区域被裁剪；z-index 再高也无效。
- 有 Teleport：弹窗被渲染到 `body` 末尾，不受父容器裁剪和局部层级限制，可自由定位和覆盖。
- 响应式来源未改变：使用 Teleport 后，数据 `open` 仍由原组件控制，事件、依赖、生命周期保持一致。
- 维护更简单：只切换 `to` 目标即可调整挂载位置，无需手动操作 DOM。
