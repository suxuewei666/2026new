### js报错修改这块怎么做的？有没有遇到不好解决的bug，怎么处理的
一般先通过监控平台看错误信息、堆栈、页面地址、用户信息和版本号。

常见捕获方式：

- `window.onerror` 捕获同步 JS 错误
- `unhandledrejection` 捕获 Promise 错误
- Vue 用 `Vue.config.errorHandler`
- 请求错误在 axios 拦截器中统一处理

处理流程：看影响范围 -> sourcemap 还原源码 -> 结合用户路径和接口日志复现 -> 修复发版 -> 观察错误量。

不好解决的 bug 多是偶现问题，比如白屏、机型兼容问题。解决时会增加关键日志、灰度发布、对比版本差异，逐步缩小范围。

### 2.vue2和vue3区别 常考
主要区别：

- 响应式：Vue2 用 `Object.defineProperty`，Vue3 用 `Proxy`
- API：Vue2 以 Options API 为主，Vue3 支持 Composition API
- 性能：Vue3 编译和 diff 优化更多，性能更好
- TS：Vue3 对 TypeScript 支持更好
- 组件结构：Vue3 支持 Fragment，多根节点
- 生命周期：`destroyed` 改为 `unmounted`

总结：Vue3 更适合大型项目，逻辑复用和类型支持更好。

### 3.nextTick原理

Vue 的 DOM 更新是异步的。数据变化后，Vue 不会立即更新 DOM，而是把更新任务放进队列，同一轮事件循环里的多次变化会合并。

`nextTick` 的作用是在 DOM 更新完成后执行回调。

底层优先使用微任务，比如 `Promise.then`，不支持时再降级到 `MutationObserver`、`setImmediate`、`setTimeout`。

使用场景：修改数据后，需要马上读取最新 DOM。

### 4.组件封装思路？颗粒度考虑（经常问）
组件封装看三个点：单一职责、复用性、维护成本。

- 基础组件：颗粒度细，比如 Button、Input、Dialog
- 业务组件：颗粒度适中，比如任务卡片、用户列表
- 页面组件：负责数据请求和流程编排

封装时要设计好 `props`、事件、插槽，避免组件内部写死太多业务。

颗粒度太细会导致文件多、传参复杂；太粗会导致复用困难。一般按职责和复用频率来拆。

### 5.事件循环
事件循环顺序：

1. 执行同步代码
2. 清空微任务队列，比如 `Promise.then`
3. 执行一个宏任务，比如 `setTimeout`
4. 再清空这个宏任务产生的微任务

```js
console.log(1);
setTimeout(() => console.log(2));
Promise.resolve().then(() => console.log(3));
console.log(4);
```

输出：`1 4 3 2`。

### 6.事件委托
事件委托是把子元素事件绑定到父元素上，通过事件冒泡统一处理。

优点：

- 减少事件绑定数量
- 动态新增元素也能触发
- 方便统一管理

```js
document.querySelector('ul').addEventListener('click', e => {
  if (e.target.tagName === 'LI') {
    console.log(e.target.textContent);
  }
});
```

### 7.promiseAll手写
```js
function promiseAll(list) {
  return new Promise((resolve, reject) => {
    const result = [];
    let count = 0;

    if (list.length === 0) {
      resolve([]);
      return;
    }

    list.forEach((item, index) => {
      Promise.resolve(item).then(res => {
        result[index] = res;
        count++;
        if (count === list.length) {
          resolve(result);
        }
      }).catch(reject);
    });
  });
}
```

特点：全部成功才成功，一个失败就失败，返回结果顺序和入参一致。

### 8.数组拍平手写 常考
```js
function flatten(arr) {
  const result = [];

  for (const item of arr) {
    if (Array.isArray(item)) {
      result.push(...flatten(item));
    } else {
      result.push(item);
    }
  }

  return result;
}
```

### 9.数组转树手写 常考
```js
function arrayToTree(list) {
  const map = {};
  const tree = [];

  list.forEach(item => {
    map[item.id] = { ...item, children: [] };
  });

  list.forEach(item => {
    const node = map[item.id];
    if (item.parentId == null) {
      tree.push(node);
    } else {
      map[item.parentId]?.children.push(node);
    }
  });

  return tree;
}
```

核心：先建 id 映射，再根据 `parentId` 找父节点。

### 10.react用过没
有简单使用。React 主要是组件化和状态驱动视图，常用 Hooks 有 `useState`、`useEffect`、`useMemo`、`useCallback`。

和 Vue 相比，React 更偏函数式，JSX 灵活度高；Vue 模板和响应式系统更适合快速开发。

### 11.created和mounted的区别
`created`：实例创建完成，数据、方法已经可用，但 DOM 还没挂载。适合初始化数据、发请求。

`mounted`：DOM 已经挂载完成，可以操作 DOM、初始化图表、绑定第三方库。

简单说：需要数据用 `created`，需要 DOM 用 `mounted`。

### 12.activated
`activated` 是 `keep-alive` 缓存组件重新激活时触发的生命周期。

常用于页面从缓存中回来时刷新数据、恢复滚动位置、重新启动定时器。

对应的 `deactivated` 是组件被缓存、离开当前页面时触发。

### 13.生命周期顺序
Vue2 常见顺序：

创建阶段：`beforeCreate` -> `created`

挂载阶段：`beforeMount` -> `mounted`

更新阶段：`beforeUpdate` -> `updated`

销毁阶段：`beforeDestroy` -> `destroyed`

如果组件被 `keep-alive` 缓存，还会有 `activated` 和 `deactivated`。

### 14.computed和watch的区别
`computed` 是计算属性，依赖数据变化后自动重新计算，有缓存。适合根据已有数据得到新值。

`watch` 是监听器，监听某个数据变化后执行副作用。适合发请求、异步操作、复杂逻辑。

区别：

- computed 有缓存，watch 默认没有
- computed 更偏“算结果”
- watch 更偏“监听变化后做事情”

### 15.路由守卫
路由守卫用于在路由跳转前后做控制。

常见类型：

- 全局守卫：`beforeEach`、`afterEach`
- 路由独享守卫：`beforeEnter`
- 组件内守卫：`beforeRouteEnter`、`beforeRouteUpdate`、`beforeRouteLeave`

常见场景：登录鉴权、权限判断、页面埋点、离开页面前确认。

### 16.路由两种模式
Vue Router 常见两种模式：

- hash 模式：URL 带 `#`，如 `/#/home`，兼容性好，不需要服务端配置
- history 模式：URL 更正常，如 `/home`，需要服务端配置 fallback，否则刷新可能 404

hash 通过监听 `hashchange` 实现；history 通过 `pushState`、`replaceState` 和 `popstate` 实现。

### 17.页面挂载在哪个生命周期里 mounted

页面 DOM 挂载完成是在 `mounted`。

常见生命周期用途：

| 生命周期 | 时机 | 主要用途 |
| --- | --- | --- |
| created | 实例创建完成，DOM 未生成 | 数据初始化、接口请求 |
| beforeMount | 模板编译完成，未挂载 | 挂载前最后处理 |
| mounted | DOM 挂载完成 | DOM 操作、第三方库初始化 |
| beforeUpdate | 数据更新前，DOM 更新前 | 获取更新前状态 |
| updated | 数据更新后，DOM 更新后 | 依赖新 DOM 的操作 |
