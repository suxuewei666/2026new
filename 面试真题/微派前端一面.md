### 1.reactive 和 ref 区别

reactive 用来处理对象、数组，返回 Proxy 代理对象，访问属性不需要 `.value`。

ref 可以处理基本类型和对象，返回 `{ value }` 结构，JS 中读写需要 `.value`，模板里会自动解包。

本质区别：reactive 依赖 Proxy 代理对象，不能直接代理 number、string 这类基本类型；ref 是把值包一层对象，通过 `.value` 做依赖收集。

### 2.虚拟dom, 好处

虚拟 DOM 是用 JS 对象描述真实 DOM 结构。

更新时先生成新的虚拟 DOM，再和旧虚拟 DOM 做 diff，找出最小变更，最后批量更新真实 DOM。

好处：

- 减少直接操作 DOM 的次数，提升性能
- 抹平平台差异，方便跨平台渲染
- 让 UI 更新变成数据驱动，代码更好维护

### 3.jsBridge npm 包详细说说，你做了什么

我主要做的是把 H5 和 App 原生通信能力封装成统一 npm 包。

核心工作：

- 统一 JS 调原生的调用方式，比如 `callNative(method, params)`
- 统一原生回调 H5 的处理，比如 callbackId 映射 Promise
- 做环境判断，区分 iOS、Android、普通浏览器
- 增加超时、异常兜底、参数校验
- 输出 TypeScript 类型，方便业务侧使用

价值是业务不用关心不同端的 bridge 差异，只调用统一 API。

### 4.任务中心重构是你主动推的吗？测试资源怎么去协调的

是主动推动的。原因是旧任务中心逻辑耦合严重，新增任务类型成本高，线上问题定位困难。

我的做法：

- 先梳理旧逻辑和风险点，拆成任务列表、状态流转、奖励领取等模块
- 和产品确认重构范围，避免需求边界扩大
- 和后端确认接口兼容方案，降低联调风险
- 提前给测试同步改动点、影响范围和重点用例
- 分阶段提测，核心链路优先测，非核心能力回归测

测试资源不足时，会提供自测清单、接口 mock、关键路径说明，帮助测试更快覆盖风险点。

### 5.手写一个出现字符最多的函数，例如：abeef 输出 {'e', 2}

```js
function maxChar(str) {
  const map = {};
  let maxKey = '';
  let maxCount = 0;

  for (const ch of str) {
    map[ch] = (map[ch] || 0) + 1;
    if (map[ch] > maxCount) {
      maxCount = map[ch];
      maxKey = ch;
    }
  }

  return { [maxKey]: maxCount };
}

console.log(maxChar('abeef')); // { e: 2 }
```

### 6.手写回文字符串个数，例如 a输出1，aa输出3, aaa输出6

思路：以每个字符、每两个字符中间为中心向两边扩散，统计所有回文子串。

```js
function countPalindrome(str) {
  let count = 0;

  function expand(left, right) {
    while (left >= 0 && right < str.length && str[left] === str[right]) {
      count++;
      left--;
      right++;
    }
  }

  for (let i = 0; i < str.length; i++) {
    expand(i, i); // 奇数长度
    expand(i, i + 1); // 偶数长度
  }

  return count;
}

console.log(countPalindrome('a')); // 1
console.log(countPalindrome('aa')); // 3: a、a、aa
console.log(countPalindrome('aaa')); // 6
```

### 7.埋点关键路径介绍一下

埋点关键路径一般是：

1. 明确埋点需求：事件名、触发时机、上报字段
2. 前端接入埋点 SDK 或封装统一上报方法
3. 在关键行为触发时上报，比如曝光、点击、提交、支付成功
4. 补充公共参数，比如用户 id、页面、设备、版本、渠道
5. 做失败重试、批量上报、离线缓存等兜底
6. 上线后和数据平台校验数据是否准确

重点是事件不能漏、字段要统一、触发时机要准确。

### 8.js报错怎么上报的，怎么处理解决的

常见上报方式：

- `window.onerror` 捕获 JS 运行错误
- `window.addEventListener('unhandledrejection')` 捕获 Promise 错误
- 框架层捕获，比如 Vue 的 `errorHandler`
- 接口错误在请求拦截器里统一上报

上报内容包括错误信息、堆栈、页面地址、用户信息、浏览器、版本号、操作路径。

处理流程：

1. 先看错误量和影响范围
2. 根据 sourcemap 还原源码位置
3. 结合用户操作路径和接口日志复现问题
4. 修复后发版，并观察错误量是否下降

### 9.宏任务、微任务输出

事件循环顺序：

1. 先执行同步代码
2. 清空所有微任务，比如 `Promise.then`、`queueMicrotask`
3. 执行一个宏任务，比如 `setTimeout`
4. 再清空这个宏任务产生的微任务

例子：

```js
console.log(1);

setTimeout(() => {
  console.log(2);
});

Promise.resolve().then(() => {
  console.log(3);
});

console.log(4);
```

输出：`1 4 3 2`。
